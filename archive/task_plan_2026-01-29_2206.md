# 任务计划: 并行 TUI 灰色折中 + Shift+Enter 强制换行

## 目标
1) 灰色样式：`Color::Gray` 在部分终端主题下接近白色，太亮；`Color::DarkGray` 又太暗。
   - 需要一个介于两者之间的“提示灰”。

2) Chat 输入：在你的环境里 `Shift+Enter` 仍不生效，但 `Ctrl+J` 可以。
   - 目标是像 Codex 一样，必须支持 `Shift+Enter` 换行。

## 阶段
- [x] 阶段1: systematic-debugging 根因调查（为什么拿不到 Shift+Enter）
- [x] 阶段2: 实现：启用 kitty keyboard protocol（让 Enter 修饰键可区分）
- [x] 阶段3: 实现：引入折中灰（Indexed 245）并替换提示/标签样式
- [x] 阶段4: `cargo fmt` + `cargo test` 全量验证
- [x] 阶段5: 记录到 `notes.md` / `WORKLOG.md` / `ERRORFIX.md`

## 关键问题
1) 为什么 Codex 能区分 `Shift+Enter`，而我们这里不行？
2) 如何在不引入 truecolor 不稳定性的前提下，得到稳定的“中灰”？

## 做出的决定
- [决定] 用 crossterm 的 `PushKeyboardEnhancementFlags(KeyboardEnhancementFlags::DISAMBIGUATE_ESCAPE_CODES)` best-effort 启用 kitty keyboard protocol。
  - [理由] 这是 crossterm 官方为“修饰键歧义”提供的机制；能最大概率让 `Shift+Enter` 在支持的终端里工作。
- [决定] 用 `Color::Indexed(245)` 作为 `DarkGray` 与 `Gray` 的折中灰，并集中到 `crates/ralph-tui/src/theme.rs`。
  - [理由] `Color::Gray` 在部分主题下过亮；`Rgb` 依赖 truecolor 且在某些环境不稳定；256 色更可控。

## 遇到错误
- [错误] `cargo test` 编译失败：`ralph-cli` 调用 `Tui::with_parallel_markdown_rendering(...)`，但 `ralph-tui::Tui` 未实现该方法。
  - [决议] 在 `crates/ralph-tui/src/lib.rs` 补齐兼容接口（先最小实现，后续再把渲染模式真正贯通到输出渲染管线）。
