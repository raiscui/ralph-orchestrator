# 笔记：并行 example（parallel-trigger-routing）重复触发排查 + E2E 计数口径

## 1. 预期（来自 `examples/parallel-trigger-routing/ralph.yml`）
- `spec_writer.triggers = ["spec.start", "spec.rejected"]`
  - 预期：`job_runs == 2`
- `spec_reviewer.triggers = ["spec.ready"]`
  - 预期：`job_runs == 2`
- `spec_logger.triggers = ["spec.ready", "spec.rejected"]`，且 `instances=2`
  - 预期：`job_runs == 3`（2×ready + 1×rejected）

## 2. “次数”口径：instance vs job（必须区分）
- **instance 数**（`spec_writer#1/#2`）会受 autoscale 影响，可能波动。
- **job_runs** 才是我们要断言的“这个 hat 实际执行了多少次工作”：
  - 并行日志里每行会带 `job=<id>`。
  - 同一 job 会输出多行，因此必须按 `job_id` 去重后再计数。
  - 计数最后要按 hat 聚合（`spec_writer#*` 汇总到 `spec_writer`）。

## 3. “event 文件给谁用”——两条链路（别混淆）

### 3.1 Hat 输出事件（工作流事件）
- job 结束后通过 channel 传给 supervisor（例如 `HatInstanceEvent::JobCompleted`）。
- 这类事件**不是从文件读**的。
- 但它们通常会被写入 `.ralph/events.jsonl` 作为历史/排障记录。

### 3.2 外部注入事件（`ralph emit`）
- `ralph emit` 会把事件写进 `.ralph/current-events` 指向的 JSONL 文件。
- supervisor/event_loop 会从该文件“增量读取新行”并注入系统。
- 同一进程内不会重复读同一行：reader 维护 file position（所以一般不需要“写回标记已消费”）。

结论：
- `.ralph/events.jsonl` 更像“历史日志/回放/排障锚点”。
- `.ralph/current-events` 指向的文件才是“外部输入事件流”。

## 4. 现场证据

### 4.1 example 目录的 `.ralph/events.jsonl` 是 append-only（会跨 run 叠加）
- 文件：`examples/parallel-trigger-routing/.ralph/events.jsonl`
- 统计（topic → count）：
  - `spec.start`: 3
  - `spec.ready`: 5
  - `spec.rejected`: 2
  - `spec.approved`: 2
- 这更像“你连续跑了多次 demo”，而不是“单次 run 重复触发”。

### 4.2 E2E keep-workspace 的单次 run 事件序列
- workspace：`.e2e-tests/parallel-trigger-routing-example/`
- 文件：`.e2e-tests/parallel-trigger-routing-example/.ralph/events.jsonl`
- 序列（按出现顺序）：
  1) `spec.start`
  2) `spec.ready`
  3) `spec.rejected`
  4) `spec.ready`
  5) `spec.approved`

该序列符合预期闭环。

## 5. 待验证的“单次 run 异常”可能根因（如果你能提供那次 stdout，就能快速定位）
- H1：`ralph#1` 重复发布 `spec.start`（starting_event 重复触发）。
- H2：`spec_writer` 的 version:2 文本里仍包含 `version: 1` 字样，导致 reviewer 再次 reject。
- H3：某个 job 输出了多个 `<event ...>`（解析出多条事件），导致路由次数膨胀。

## 6. `hats.<id>.description` 会不会注入到 prompt？
- 会：用于“协调者 prompt”里的拓扑表格，帮助 Ralph 理解该 hat 的用途。
  - 非并行：`## HATS` 表格里有 `Description` 列。
  - 并行：`## HATS TOPOLOGY (CONFIGURED)` 表格里有 `description` 列。
- 不会：不会自动进入每个 hat 的 job prompt（job prompt 主要由 `instructions` + `Incoming Events` 组成）。
