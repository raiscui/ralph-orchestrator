## 2026-03-05 21:11 +0800 | 加固修复: 兼容 `<event` opening tag 多行格式,避免 Rendered 下继续被吞

- 之前的展示层改写只匹配 `<event ` (event 后必须紧跟空格)。
- 但模型/后端偶发会把 opening tag 格式化成多行,例如:
  - `<event\n  topic="reply.human.message" ...>`

### 修复(最小侵入,只改展示层)

- `ralph-adapters`: 识别 `<event` 后跟任意空白(空格/\t/\n)或 `>` 的 opening tag,不再只认 `<event `。
- 同步把 nested event 的检测从 `<event ` 改为 `<event`。

### 回归与验证

- 新增/加强单测锁定该边界:
  - `crates/ralph-adapters`: `markdown_rendered_mode_shows_reply_human_message_payload_with_multiline_opening_tag`

- 如果 `event.topic` 命中 `TopicContract`,会走 contract 路由:
  - `route_event -> deliver_fanout / deliver_queue -> deliver_to_instance_id`
- 如果没有命中 `TopicContract`,会走默认 trigger-driven 路由:
  - `route_event -> route_event_via_triggers -> choose_ralph_instance_for_delivery -> deliver_fanout`
- 对 `source/source_instance` 不为空的内部事件,`allow_secondary=false`,因此即便 `ralph#1` 忙,也仍回到主实例 pending 队列。
