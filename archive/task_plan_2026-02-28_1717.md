## 目标

- ralph#1 对 human 的“回复消息”不再用 `<event topic="human.message" ...>`:

  - 仍然允许 TUI 展示该事件(作为“聊天回复”)。
- app-server trace 能看到 turn/start 注入的 prompt:
  - 在 `RALPH_CODEX_APP_SERVER_TRACE=1` 且 `RALPH_CODEX_APP_SERVER_TRACE_STEER_INPUT=1` 时,
    stderr 输出包含 `turn/start` 的 `input_len` 与 `input_preview`(截断)。

## 现象

1) topic 语义混用:
- 当前 ralph#1 收到 `human.message` 后,会用同一个 topic `human.message` 做“回复”。
- 这会让 `human.message` 同时承担:
  - 外部输入(human -> hats)
  - 输出回复(hats -> human)

2) trace 缺少启动注入信息:
- 使用:
  - `RALPH_CODEX_APP_SERVER_TRACE=1`
  - `RALPH_CODEX_APP_SERVER_TRACE_STEER_INPUT=1`
  - `ralph run ...`
- 仍然看不到 `turn/start` 注入的 ralph prompt(user/sys 等文本)。
- 你反馈以前 `codex exec` 时,这些内容会出现在 stderr,因此可审计。

- `human.message` 语义没有区分输入/输出,导致阅读与路由都容易产生歧义。

- 规则:
  - 输入: 仍使用 `human.message`。
  - 输出: ralph#1 回复 human 时使用 `reply.human.message`。
  - Supervisor: `reply.human.message` 仅用于 UI 展示,不参与路由。
- 好处:
  - 不再依赖“hat-sourced human.message UI-only”这种隐式判定。
  - 读日志/抓取证据时更清晰: `human.message`=输入,`reply.human.message`=回复。

### 方案B(不推荐): 继续用 `human.message`,靠路由护栏兜底

- 风险:
  - topic 语义仍混乱。
  - 很容易在其他场景里再次踩到“人类以为是输入,系统当成输出”之类的理解偏差。

# 任务计划: 并行模式 command lanes(借鉴 openclaw lane + generation + draining,降低并发 flaky)(2026-02-28 15:30 +0800)

## 目标

- 在 parallel 模式下,把 orchestrator 自己执行的“有副作用的命令/动作”(尤其是 workspace/git worktree)纳入 lane 管理:
  - 避免多个 HatInstance 并发触发 `git worktree add/remove` 造成锁冲突/偶发失败.
  - 在 shutdown/early-exit 时,用 draining 语义做确定性收尾,减少 worktree 泄漏与 warning.
- 设计对齐 openclaw 的 `CommandLane`/`command-queue.ts` 的核心点:
  - lanes: 不同风险/交互面的任务隔离.
  - generation: reset/early-exit 时 bump,忽略 stale completion.
  - draining: 明确拒绝新任务,避免“静默被 kill”.

## 两个方向(需要择一)

### 方案A(最小改动,先能用): 全局 semaphore 串行化 worktree add/remove

- 在 `HatInstanceActor` 的 worktree acquire/release 前后,用一个全局 `Semaphore(1)` 做互斥.
- 优点:
  - 改动小,能快速解决 git worktree 并发锁冲突.
- 缺点:
  - 无 generation/reset/clear 语义.
  - shutdown 的 draining 语义不够清晰,后续仍可能演化出“靠 if/flag 贴补丁”.

### 方案B(对齐 openclaw,推荐): 实现 CommandQueue(lanes + generation + draining),并用于 workspace/git 操作与 shutdown drain

- 新增最小 `CommandQueue`:
  - `acquire(lane)` 返回 permit,permit drop 时释放并唤醒队列.
  - `mark_draining()` 拒绝新 acquire(返回专用错误).
  - `clear_lane()` 拒绝排队中的 waiter(返回专用错误).
  - `reset_all_lanes()` bump generation + 清空 active,忽略 stale release,并立刻 drain.
- 把 `git worktree add/remove` 放进 `workspace.git` lane(默认 max_concurrent=1).
- 改良 HatInstance shutdown:
  - `Shutdown` 不再立刻 break 丢弃 in-flight job.
  - 进入 draining: cancel 当前 job,并确保 best-effort 释放 worktree(必要时跳过 hooks,保证退出可控).

## 做出的决定

- [决定] 采用方案B(对齐 openclaw lane + generation + draining).
- [理由] 你明确选择了 "1",且该方案能把并发 flaky 与 shutdown 收尾变成可复用的硬机制,避免后续到处加 if.
