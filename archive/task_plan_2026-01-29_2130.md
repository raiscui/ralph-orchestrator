# 任务计划: TUI 鼠标框选复制/粘贴（Clipboard 集成）

## 目标
1) 在 TUI 内用鼠标框选（蓝色高亮）输出内容后，用户能在 macOS 里直接 `Command+C` / `Command+V` 完成复制粘贴闭环。
   - 这里的“复制粘贴闭环”指：选中后，剪贴板里确实有文本，能粘贴到任意应用（或回到 TUI 的 chat 输入框）。

2) 支持 `Paste` 事件：即使终端使用 bracketed paste，`Command+V` 也能把文本送进 chat 输入框（或搜索框）。

3) 行为要可解释：在帮助面板/状态栏提示用户如何复制（避免“我选中了但怎么都复制不出来”的困惑）。

## 方案（给自己看的取舍）
1) 不惜代价，最佳方案（更贴合用户直觉）：
   - **鼠标框选结束（MouseUp）自动复制到剪贴板**（best-effort），用户无需额外按键；
   - 额外提供显式快捷键（例如 `y`）再次复制；
   - 剪贴板写入优先使用 OSC52（跨平台/远程可用），并在 macOS 上增加 `pbcopy` 兜底。

2) 先能用，后面再优雅（风险更低）：
   - 不做自动复制，只提供 `y` 复制；
   - 先支持 `Event::Paste`（保证粘贴可用）。

## 阶段
- [x] 阶段1: 写 spec + 更新 task_plan 日志
- [x] 阶段2: 调查现状（为什么 Cmd+C 不工作、Paste 是否被忽略）
- [x] 阶段3: 实现复制/粘贴闭环（输出选择 + chat 选择 + Paste event）
- [x] 阶段4: 增量测试（unit + TUI snapshot/渲染 smoke）
- [x] 阶段5: `cargo test` 全量验证 + 记录结论（WORKLOG/ERRORFIX）

## 关键问题
1) 当前 TUI 处于 raw mode + mouse capture，终端是否还能做“原生文本选择”？（通常不行/需按特殊键）
2) 当前框选是“应用内高亮”，如何把它转换成“可复制的文本”？（需要从渲染缓冲区反推或复用渲染器）
3) `Event::Paste` 目前是否被忽略？如果忽略，粘贴会完全无效（取决于终端是否发送 Paste 事件）。

## 做出的决定
- [决定] 优先走“最佳方案”：MouseUp 自动复制 + `y` 显式复制；同时支持 `Event::Paste`。
  - [理由] 你现在的肌肉记忆是 `Cmd+C/Cmd+V`，自动复制能最大程度贴合；`y` 作为兜底/可发现性增强。
